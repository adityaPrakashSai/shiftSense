# data/

- `seed/ward.json`: default synthetic ward, 20 regular + 4 standby nurses, 14 days from Mon 26 Oct
  2026 (`SEED=default`), generated by `scripts/gen_ward.py`.
- `seed/mini_ward.json`: 9-nurse, 14-day synthetic mini ward (`SEED=mini`), with scenarios A–D.
- `seed/real_ward_a.json`: pseudonymized October ward from Hospital A (`SEED=real_a`).
- `seed/mini_baseline.json`: the mini ward's solved and published state (tier vector 3/0/0/19/55),
  loaded into an empty database instead of solving, so every clone, reset and deployment starts
  from the same roster (CP-SAT with several workers does not return the same one twice). Rebuild
  with `uv run python -m scripts.demo_baseline` after editing `mini_ward.json`.
- `llm_cache.jsonl`: committed Muse Spark responses (evals and the scripted demo), imported at
  startup; replay mode needs nothing else. Run ids are stored as `run-ref-N` placeholders.
- `shiftsense.db`: the SQLite database, created at runtime (git-ignored), with
  `shiftsense.snapshot-<seed>.db` beside it for Reset demo.

Synthetic or pseudonymized data only: no real names, hospitals, photos or patient data.
