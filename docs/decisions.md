# Design decisions log

One line per non-obvious choice (design doc 11.4 rule 9): date, decision, reason.

- 2026-10-28 · Python env and deps managed with `uv` (`uv.lock` committed) · fast, reproducible installs; Docker uses `uv sync --frozen`.
- 2026-10-28 · `LLM_MODE` defaults to `live` in code but `.env.example` sets `mock`, and `make setup` copies it to `.env` · deployed app is live by default; a fresh clone runs offline with no keys.
- 2026-10-28 · `/api/health` reports `db` as `ok` / `absent` / `error` and opens SQLite read-only · a health check must not create the database file.
- 2026-10-28 · `make test` also runs `ruff format --check` · keeps generated code tidy (3.3).
- 2026-10-28 · `reference/` is excluded from ruff and from `make test`; run it with `make reference` · it is spec code, not app code (reference/README.md).
- 2026-10-28 · The fixtures zip was unpacked at the repo root (`data/seed/`, `tests/fixtures/`, `reference/`) and the design doc lives at `docs/DESIGN.md` · matches CLAUDE.md.
- 2026-10-28 · `SolveInput` splits hard availability into `unavailable` (sick/emergency), `leave` and `night_exempt` instead of one set · each maps 1:1 to a hard group in 5.2, so constraint names (`leave:N04:d2`) and the leave credit for `CONTRACT_MIN` need no extra lookup.
- 2026-10-28 · `SolveInput.standby_allowed` (False in full runs) carries the `standby_off_roster` rule; `Pref` has an optional `shift` so one type serves day-off, wanted and avoided prefs; `NurseHistory` adds `mornings` for `FAIR_MORNINGS` · fields 4.3 implies but does not list.
- 2026-10-28 · Carry-in history lives in a `ward_history` table (one JSON row per ward) · 4.4 has no home for it; seeds only give totals over earlier periods, not per-period rows. Per-period fairness history (US-12) will come from published runs.
- 2026-10-28 · `Ward.priorities` holds the tier order · `GET /api/ward` returns it (10.1) and the P1 settings panel edits it per ward.
- 2026-10-28 · Contract scaling rounds to 6 decimals before floor/ceil; `max_nights` = ceil(per_month x days / 30) as in the reference solver (3 per 14 days, 7 for real_a's 31 days) · avoids float noise turning 11.0 into 12.
- 2026-10-28 · Fixed duties (`Nurse.fixed_duty`) become `Forcing("fixed_duty", ...)` except on the nurse's leave or whole-day unavailable days · real_a's ANS has GH leave on 2 and 20 Oct, which would otherwise contradict her G duty.
- 2026-10-28 · Default seed `data/seed/ward.json` is generated by `scripts/gen_ward.py` (deterministic); all 20 regular nurses are night-qualified and standby S04 (trainee) is not · 56 target nights with a cap of 3 per nurse needs at least 19 night-capable regular nurses; S04 gives the counterfactual test (11.3) its non-night-qualified trainee.

- 2026-10-28 · An empty database is migrated and seeded with `SEED` at app startup; `make seed` deletes and recreates it · matches 11.1 ("seed if empty") and keeps reset simple.
- 2026-10-28 · M2 hard groups beyond the 5.2 tables: `max_nights:{n}` (5.2 text), `standby_off_roster:{n}:d{d}` (4.1), and `ans_general_duty:{n}:d{d}` (the ANS never works M/E/N; 4.1 roles) · each is a rule the design states in prose but does not list as a row. None is waivable.
- 2026-10-28 · The G (general duty) variable exists only on cells where G is forced (fixed duty) or published; the validator reports any other G as `general_duty_forced_only` · keeps G out of the search space for everyone else; G counts as worked for runs, `max_shifts` and hours, never for coverage, and counts as a day shift for `rest_after_night`.
- 2026-10-28 · Sliding-window names use the window's last day (`max_consecutive_days:N02:d0` = the run that day 0 would extend past K) and the validator reports each day a run exceeds K · model and validator agree name for name, which the `rule_check` test relies on.

- 2026-10-28 · `solve()` runs the independent validator on every roster and raises if it reports anything · a disagreement between model and validator is a solver bug and must never reach a published run.
