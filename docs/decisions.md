# Design decisions log

One line per non-obvious choice (design doc 11.4 rule 9): date, decision, reason.

- 2026-10-28 · Python env and deps managed with `uv` (`uv.lock` committed) · fast, reproducible installs; Docker uses `uv sync --frozen`.
- 2026-10-28 · `LLM_MODE` defaults to `live` in code but `.env.example` sets `mock`, and `make setup` copies it to `.env` · deployed app is live by default; a fresh clone runs offline with no keys.
- 2026-10-28 · `/api/health` reports `db` as `ok` / `absent` / `error` and opens SQLite read-only · a health check must not create the database file.
- 2026-10-28 · `make test` also runs `ruff format --check` · keeps generated code tidy (3.3).
- 2026-10-28 · `reference/` is excluded from ruff and from `make test`; run it with `make reference` · it is spec code, not app code (reference/README.md).
- 2026-10-28 · The fixtures zip was unpacked at the repo root (`data/seed/`, `tests/fixtures/`, `reference/`) and the design doc lives at `docs/DESIGN.md` · matches CLAUDE.md.
- 2026-10-28 · `SolveInput` splits hard availability into `unavailable` (sick/emergency), `leave` and `night_exempt` instead of one set · each maps 1:1 to a hard group in 5.2, so constraint names (`leave:N04:d2`) and the leave credit for `CONTRACT_MIN` need no extra lookup.
- 2026-10-28 · `SolveInput.standby_allowed` (False in full runs) carries the `standby_off_roster` rule; `Pref` has an optional `shift` so one type serves day-off, wanted and avoided prefs; `NurseHistory` adds `mornings` for `FAIR_MORNINGS` · fields 4.3 implies but does not list.
- 2026-10-28 · Carry-in history lives in a `ward_history` table (one JSON row per ward) · 4.4 has no home for it; seeds only give totals over earlier periods, not per-period rows. Per-period fairness history (US-12) will come from published runs.
- 2026-10-28 · `Ward.priorities` holds the tier order · `GET /api/ward` returns it (10.1) and the P1 settings panel edits it per ward.
- 2026-10-28 · Contract scaling rounds to 6 decimals before floor/ceil; `max_nights` = ceil(per_month x days / 30) as in the reference solver (3 per 14 days, 7 for real_a's 31 days) · avoids float noise turning 11.0 into 12.
- 2026-10-28 · Fixed duties (`Nurse.fixed_duty`) become `Forcing("fixed_duty", ...)` except on the nurse's leave or whole-day unavailable days · real_a's ANS has GH leave on 2 and 20 Oct, which would otherwise contradict her G duty.
- 2026-10-28 · Default seed `data/seed/ward.json` is generated by `scripts/gen_ward.py` (deterministic); all 20 regular nurses are night-qualified and standby S04 (trainee) is not · 56 target nights with a cap of 3 per nurse needs at least 19 night-capable regular nurses; S04 gives the counterfactual test (11.3) its non-night-qualified trainee.
- 2026-10-28 · Supply/demand sanity test runs on the default and mini wards only · real_a's printed month has Σ min contract 462 against 339 target slots (three nurses on whole-month ML, one on study leave), so the bracket does not hold there by design.
- 2026-10-28 · Fixture doubt (not edited): real_a's ANS has `consecutive_days = 3` while `last_days` is `["-", "-", "-"]` · G duty is recorded as off in `last_days`; M2's carry-in rules should treat the ANS's run length as the source of truth or skip her, since G is outside coverage.
- 2026-10-28 · An empty database is migrated and seeded with `SEED` at app startup; `make seed` deletes and recreates it · matches 11.1 ("seed if empty") and keeps reset simple.
- 2026-10-28 · M2 hard groups beyond the 5.2 tables: `max_nights:{n}` (5.2 text), `standby_off_roster:{n}:d{d}` (4.1), and `ans_general_duty:{n}:d{d}` (the ANS never works M/E/N; 4.1 roles) · each is a rule the design states in prose but does not list as a row. None is waivable.
- 2026-10-28 · The G (general duty) variable exists only on cells where G is forced (fixed duty) or published; the validator reports any other G as `general_duty_forced_only` · keeps G out of the search space for everyone else; G counts as worked for runs, `max_shifts` and hours, never for coverage, and counts as a day shift for `rest_after_night`.
- 2026-10-28 · Sliding-window names use the window's last day (`max_consecutive_days:N02:d0` = the run that day 0 would extend past K) and the validator reports each day a run exceeds K · model and validator agree name for name, which the `rule_check` test relies on.
- 2026-10-28 · Carry-in runs come from `consecutive_days` / `consecutive_nights`, while `rest_after_night` at d = -1 reads `last_shifts` · matches the reference solver and plan_check.py; for real_a's ANS (G recorded as "-") the run length is the source of truth.
- 2026-10-28 · `RosterModel(drop_groups=...)` removes whole hard groups; used only by tests to prove each rule bites (11.3) · waivers stay per-name via `SolveInput.waived`.
- 2026-10-28 · `solve()` runs the independent validator on every roster and raises if it reports anything · a disagreement between model and validator is a solver bug and must never reach a published run.
- 2026-10-28 · The solver CLI (`app/solver/cli.py`) is the one solver module that imports outside the package, and only `app.domain.seeds` and `app.planner.build_input` (pure, no database); seed parsing moved from `app/store/seed.py` to `app/domain/seeds.py` for that · the boundary test enforces it.
- 2026-10-28 · Write-up numbers, validator on real_a's printed October plan (M2): the planned grid breaks 0 hard rules at real_a's limit of 8 consecutive days; the hand-edited update breaks 2 (`min_cover:d12:N`, `min_cover:d13:N`: nights on 13-14 Oct at 2 against a floor of 3). At the synthetic limit of 6 the plan has 8 streaks of 7-8 working days (S4, N01, N08, N09, N11, N12, N14, N16; N12's includes 2 carry-in days from September), and 27 quick returns (E then M, soft) in both versions. All match reference/real_rosters/plan_check.py.
- 2026-10-28 · M2 solve times (coverage tier only, 8 workers): default ward 0.2 s (coverage 0, proven), mini ward 0.05 s (coverage 3, proven, equal to the golden vector), real_a 0.1 s (coverage 0, proven).
- 2026-10-28 · Soft weights follow the reference solver and the interview text where they differ from the 5.3 table: `CHANGED` 2 and `STANDBY_CALLED` 1 (standby first), `SINGLE_NIGHT` 3 · the golden vector (3/0/0/19/55) was computed with these; the table's 1s predate the 26-27 Oct interviews.
- 2026-10-28 · Doubt, not changed: `FAIR_NIGHTS` keeps nurses on an announced night break in the spread, as the reference solver does, although 5.3 says to leave them out · the golden fairness value 55 depends on it (mini README finding 6 lists exclusion as a suggestion). Revisit with the head nurse; changing it means regenerating mini_expected.json offline.
- 2026-10-28 · Fairness spreads also leave out nurses away for the whole period (every day leave or unavailable) · real_a has three nurses on month-long ML and one on study leave; with them in, every spread is pinned at 0 and the solver cannot balance anyone. No mini or default nurse is affected, so the golden vector is unchanged.
- 2026-10-28 · The ANS (role `ans`) is outside the contract, sequence and fairness terms as well as coverage · she works fixed G Mon-Sat; split-weekend and isolated-day penalties on her would be constant noise.
- 2026-10-28 · Stage `best` is stored as the tier's value in the final roster; the stage's own objective is kept as `stage_best` and in the `stage.done` event · an unproven tier can be improved by a later stage, and the invariant "cost rows sum to stage best" must hold for what is published.
- 2026-10-28 · `SOLVER_TOTAL_SECONDS` (default 9) caps one full solve; each stage gets min(stage limit, time left) · the default ward's requests and fairness stages each use their full 5 s, which made the total 10.4 s against G1's 10 s.
- 2026-10-28 · Dominance weights for `solve_weighted` come from each tier's worst case (sum of weight x upper bound of its terms); spread upper bounds use history + horizon length · tight bounds keep the multipliers small enough for CP-SAT.
- 2026-10-28 · Skipped tiers emit `stage.done` with `status: "skip"`; fairness spread terms name who sets the max and the min in their detail ("max 12 (N05), min 3 (N06)") · gives the explainer (M8) something to cite without recomputing.
